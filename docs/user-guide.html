1 · Getting started

RiverCrossing is a keyboard-first desktop app for Windows and macOS. The operator types a rider's plate number and presses Enter at each lap crossing; the app records the lap, deals a card from a seeded virtual shoe, and at the finish scores every entry's best 5-card poker hand.

About RiverCrossing

Version and credits live in Help ▸ About RiverCrossing: the product name and installed version, the author line, © 2026 Mark Buckaway, and the GPL-3.0-only licence. The version comes from the installed package, so it always matches the build you are running.

Installing

  • Windows: run the installer and follow the prompts. Windows may show a SmartScreen "More info → Run anyway" step on the unsigned build — the guide documents that step so volunteers can get past it safely.
  • macOS: drag the app into Applications (or open the DMG and copy it), then launch. Gatekeeper may ask you to confirm opening an unsigned app once.

First launch & the ride library

The app opens on the timing console. When no ride is open — a fresh database, for example — an information alert explains that no ride is loaded; Ride ▸ New Ride… opens the ride setup window and File ▸ Ride Library lists every ride in the database — one database, every event. From the library you can open an existing ride, duplicate one (copies setup + riders, no timing data), or delete one (you must type the ride's name to confirm, and a backup is written first). A running ride is never deletable.

Settings

File ▸ Settings (or the app menu on macOS) controls the operator-comfort layer:

  • Appearance — System (follow the OS), Light, or Dark. All three work on both platforms. On Windows a change applies at next launch; macOS applies it live.
  • Sound on crossing — three cues: a click when a crossing records, a two-tone alert when a ride set to hold short laps flags one, and a buzz for an unknown plate or empty entry.
  • Hide times on the console — hides lap/total times mid-ride (it's-not-a-race mode). Times are still recorded underneath. The ride clock stays.
  • Verbose logging — on by default; writes a diagnostic log for support. Each launch gets its own file, rivercrossing-<date-time>.log, in your per-user configuration folder (beside your settings — ~/Library/Application Support/RiverCrossing on macOS; under %LOCALAPPDATA% on Windows). It records the launch, the ride loaded and any crash as one JSON record per line, plus — while this is on — the action trail of menu picks, dialogs opened, and button and control events. Turning it off stops the trail immediately; the newest 20 session files are kept.
  • Back up now — writes a backup immediately.

Appearance and text zoom each live on one surface: the theme radios are in Settings only (the View menu no longer mirrors them), and text zoom is View ▸ Zoom only (90–150%). Hide times on the console is the one setting with two controls — the Settings checkbox and the View-menu item — and they stay in sync.

Where your data lives

All rides live in one SQLite database (rides.db) in your user data folder. Every crossing commits as it happens (WAL journal), so a crash loses at most a keystroke. Backups are written on open and hourly while a ride runs, kept in a <db>.backups/ sibling folder, pruned to the newest 20.

2 · Setting up a ride

Ride ▸ New Ride… opens the setup window for a new ride, and Ride ▸ Edit Ride… reopens the same window preloaded with the open ride's settings — the ride lifecycle lives on the Ride menu now (the old Ride Setup… row is gone). Existing rides open from the ride library.

  • Name, date, venue, organizer, scorer, logo — the identity shown on the console and in published results. The logo file is embedded in exports.
  • Planned start & duration — the riding window; the console counts down the time to close.
  • Lap length & minimum lap time — a crossing faster than the minimum is flagged (a mistyped plate or a double entry usually explains it); the ride's short-lap policy — always deal (the default), or hold short-lap cards for review — decides what happens to its card.
  • Entries — solo only, or solo + teams (the default) with a max riders-per-team (2–10, default 4).
  • Plate model — rider-pooled (default): every rider has their own plate and draws one card per lap, uncapped; the team's hand scores from the pooled cards. Team-relay: one plate per team, one rider on course at a time.
  • The shoe — decks (default 8) and jokers per deck (0, 2, or 4; default 2). All decks are shuffled together and dealt in order; the shoe reshuffles automatically if it empties.
  • Card cap — optional cap on cards per entry; laps still count past the cap.
  • Tie-break order — how identical best hands are resolved: ① most laps, ② shortest total time, ③ high-card draw at the venue. Set it here (or reopen this dialog with Ride ▸ Edit Ride… while the ride is still a draft); like the rest of the ride's format, it locks once the ride starts.

The ride needs a name, venue, organizer, scorer and a lap length before the dialog accepts the setup — it lists exactly what is missing if you try to save without them — and the ride cannot start until those are set and the roster has at least one rider. Duration and minimum lap time must be valid H:MM and M:SS values; the planned start and date always carry a value, and the logo is optional.

Setup locks tighten once the ride starts: the ride's format (entry mode, plate model, team size, the shoe, the card cap, the tie-break order) is frozen, while the name, date, start, venue, organizer and scorer fields stay editable in a running ride.

3 · Riders & entries

Riders ▸ Rider Editor manages the roster: plates, names, and teams. Riders are entered with a first name and a last name — both required in the editor; the CSV import also accepts a single name (see Appendix B). A solo rider's entry is listed under that full name.

  • Add a solo rider, or add a rider onto an existing team by picking the team from the Team list — new teams are created in the Teams Editor, not here. Plates are unique across the ride, and a new entry's plate is prefilled with the next free number. The form also carries a Sex dropdown — blank (unknown), M, or F — which fills the Sex column in the rider lists and the CSV's sex column; an unknown sex stays blank in exports and shows no marker beside the rider's name on the published pages (see Appendix B).
  • Teams Editor — Riders ▸ Teams Editor (mixed rides only) edits a team's own record: name, notes, the team's plate on relay rides, and a logo — pick a playing card or choose an image file (an image wins if both are set). It also creates teams: with nothing selected the form becomes the Add form, and Add team builds the team from it — a blank or duplicate name is refused (duplicates are compared case-insensitively, and the same check applies when you rename on Save). Membership is read-only here; the Rider Editor owns who is on which team.
  • Delete is available while the ride is a draft; once an entry has recorded data, it is never removed — entries are marked DNF or their crossings voided instead (R-15).
  • Import / export CSV — bring a roster in from a file or write one out. One header-mapped format works for every ride (see Appendix B). The import preview lists every conflict before anything is written, so you can fix the file and re-import freely until the ride starts.
  • Teams can be reshaped up to the start; on a pooled ride, moves stay possible while running and every move is audit-logged.

4 · Running the ride

The console is keyboard-first: the operator types a plate and presses Enter. The header shows the ride's name and state: a stop light above the status word (green running · amber draft or corrections · red finished), the elapsed and remaining time as analog dials with numeric readouts, and the round GO / STOP buttons at the right.

  • Start — press the green GO button (or Ride ▸ Start Ride). A ride with no riders, or a setup missing a required field, cannot start — the app says what is missing. A stopped ride resumes with the same button and keeps all data. Missed the gun? Ride ▸ Set Start Time… back-dates the start and recomputes lap-1 times.
  • Record a crossing — type the plate, press Enter (or click Record). The crossing commits instantly, a card is dealt from the shoe, and the feed updates.
  • The sounds — a click on every recorded crossing, a two-tone alert when a ride set to hold short laps flags one, and a buzz for an unknown plate or an empty entry. Toggle them in Settings.
  • Undo — Ctrl+Z (or the Undo button) removes the last crossing and returns its card.
  • Short-lap review — in a ride set to hold short laps, a lap under the minimum is flagged and its card held until you confirm or void it; rides on the default "always deal" policy credit every lap immediately. The sidebar's Needs Review tab lists every flagged crossing; the Riders tab lists the whole roster — double-click a rider there (or select one and press Enter) to open the Rider Editor on that rider.
  • Relay teams — one rider per team is on course at a time; the crossing credits the team.
  • Hide times — Settings (or the View menu) can hide lap/total times mid-ride; times are still recorded underneath and the ride clock stays visible.

5 · Fixing mistakes

Every correction is a command with a reason, and every one is written to the audit log — nothing is ever deleted, only voided or edited (R-33).

  • Undo last crossing — the fastest fix for a mistyped plate.
  • Edit a crossing — change its time, or void it. Later lap times for the entry recompute automatically.
  • Add a crossing at time — a rider missed at the line; give the plate and the exact time.
  • Reassign a plate — move a crossing to the plate it belonged to; the card moves with it.
  • Deal / void a manual card — fix a mis-dealt card; a manual deal takes the next card from the shoe.
  • Mark DNF — an entry that did not finish keeps its laps and cards and is listed in the DNF block. Reversible.
  • Audit trail — Ride ▸ Audit Trail… shows every action (who, when, what, entry, reason), newest first, with plate search and action filters.

The Entry Detail window shows one entry's laps, cards, and current hand, with the correction buttons (edit crossing, deal/void card, move rider, mark DNF) on the same screen.

6 · Stopping, quitting & recovery

  • Stop — press Stop (or Ride ▸ Stop Ride…) and confirm the native prompt. Stopping locks the entry field and freezes the clock display at the stop instant — the ride clock keeps counting on wall time underneath, so nothing is lost — and Start resumes whenever you are ready.
  • Quit with a ride running — the exit dialog offers Cancel, Finish ride first…, or Quit — keep ride running. Quitting keeps the ride live on the wall clock; the next launch asks you to continue it (the resume dialog says whether the last exit was a clean quit or a crash).
  • Crash recovery — every crossing commits as it happens, so a crash loses at most a keystroke. The clock is wall time, so elapsed time is never lost either.
  • Backups — written on open and hourly while a ride runs, kept in a <db>.backups/ folder (newest 20). File ▸ Back Up Database… or Settings ▸ Back up now writes one on demand.

7 · Finishing & standings

  • Finish ride — Ride ▸ Finish Ride… locks entry, runs the hand evaluator's self-test (a red self-test blocks finishing, R-44), computes the final standings, and publishes the ride's HTML and PDF results into the exports folder in your user data directory. The finished banner's View results… button — or Results ▸ Standings (F5) — opens the results dialog.
  • Finish gate — the evaluator self-test runs fresh on every finish; a red result blocks it. DNF entries stay in the standings, ranked last within their kind (and marked DNF in the published pages), and held cards never count until you confirm them.
  • Ties — identical best hands are resolved by the ride's tie-break order (most laps, then total time, then high-card draw). The order is set in ride setup and locks once the ride starts; Ride ▸ Edit Ride… can still change it while the ride is a draft.
  • Reopen for corrections — Ride ▸ Reopen Ride reopens a finished ride for corrections: entry is locked, edits are highlighted in the feed, and Finish again re-locks and re-ranks. After corrections, the results dialog flags the published results as stale until you export again.
  • Continue a reopened ride — Start stays live while a ride is reopened: pressing GO (or Ride ▸ Start Ride) continues it — entry unlocks, the clock (held at the recorded finish while reopened) goes live again from the ride's original start, and that recorded finish is discarded. Finish again when the riding is truly over.

The Results dialog shows the full field with place, plate, entry, laps, best-5 cards, and the hand name, plus the publish options (below); it is modal, so close it to get back to the console. On a mixed ride the standings sit on two notebook pages — Teams and Solo — each numbered from 1 with its own DNF tail, and every list here keeps its Plate column (the plate-less team style belongs to the exports). Results ▸ Standings (F5) opens the dialog at any time — even with no ride open, where it shows an empty state.

8 · Publishing results

  • HTML export — one self-contained file you can post anywhere. On a mixed ride it renders per-kind sections: top 3 teams then top 3 solo riders on the podium; Top teams and Top solo riders (five each); Most laps split teams/solo (five each); and the Full field heading, whose Teams subsection is compact and plate-less — the team's logo sits beside its name, drawn cards in their own column — followed by the Solo riders subsection with plates. A solo ride keeps the single-kind page: top 3 podium, Top ten, Most laps top 10. Options: show lap & total times (off by default; with it off the export embeds no time data at all, and the fastest-time leaderboard cannot be requested — its checkbox is cleared and disabled while times are off), laps leaderboard, fastest-time leaderboard, full field, all cards drawn. The ride's logo is embedded either way.
  • PDF report — the same sections as the HTML export, as a printable document.
  • Podium poster — a single celebratory page for the prize table: top 3 teams plus top 3 solo riders on a mixed ride, or the top 5 solo riders on a solo ride.
  • Standings CSV — place, plate, entry, type, sex, laps, hand (and times when shown); sex is the solo rider's M/F and blank for a team. On a mixed ride the type column labels each row's Teams or Solo section, and the places restart at 1 for each.
  • Preview HTML in Browser — opens this session's last HTML export in your default browser. It needs a finished ride and an HTML export made in this session; after a restart it is disabled again until the next export.
  • Preview PDF in Browser — opens this session's last PDF export: the report or the podium poster (the poster counts as a PDF). Same gate — a finished ride plus a PDF export this session — and a CSV export enables neither preview.

9 · Poker, the run way

It is not a race — it is a poker run. Each completed lap deals one card; at the finish, every entry's best 5-card hand from all cards drawn is scored. Jokers are wild: a joker plays as any card you need.

Hand rankings, best to worst:

  1. Five of a kind (with jokers)
  2. Straight flush
  3. Four of a kind
  4. Full house
  5. Flush
  6. Straight (the wheel — A-2-3-4-5 — counts)
  7. Three of a kind
  8. Two pair
  9. One pair
  10. High card

Duplicates across entries are expected — the shoe is shuffled, not dealt from a single deck — and the shoe reshuffles automatically if it empties. Two entries with identical best hands are resolved by the ride's tie-break order, never guessed.

10 · Troubleshooting & FAQ

  • Missed the start — use Ride ▸ Set Start Time… to back-date it; lap-1 times recompute.
  • Typed the wrong plate — undo the crossing, or edit/reassign it and record a reason.
  • A rider crossed twice — void the extra crossing (its card voids with it).
  • The shoe ran out — it reshuffles automatically; deals continue.
  • Moving the database to another machine — copy rides.db (and its .backups folder if you want the history). The app opens it in place on the new machine.
  • Restoring a backup — replace rides.db with the backup file, then relaunch.
  • Theme change on Windows — a dark/light switch applies at the next launch; the status bar says so.

Appendix B — CSV reference

Every roster import and export — solo-only or mixed, rider-pooled or relay — uses one header-mapped format, with one row per rider. The app reads the file's header row and maps each column to a field by name, not by position, so you can export from a registration system, add or reorder extra columns, and it still imports.

The canonical columns

Canonical headerWhat it holdsNotes
FIRSTNAMERider's first nameAt least one of FIRSTNAME or LASTNAME must appear in the header and in each data row. The import looks for a column whose heading contains "first name" (case-insensitive).
LASTNAMERider's last nameOptional — a heading containing "last name". A rider with only one name leaves it blank.
TYPEsolo or teamMatched after case folding. A heading containing both words "solo" and "team" (such as "Solo or team?") is recognised as the type column; so is a literal type. Blank means solo, unless the row names a team.
TEAMNAMEThe team's nameBlank for solo rows. A heading containing "team name". Rows sharing a team name form one team; matching ignores case and extra spaces, so "Full Send" and "full  send" are the same team. It does not need to be unique per row — a team has one row per member.
NUMBERThe rider's or team's plateOptional — a heading that is exactly "number", "plate" or "bib". When blank, the app assigns the next free plate automatically (see below).
NOTESA note on the rider or teamOptional. A heading containing "note" or "notes". Team notes from member rows are joined into one team note on import.
SEXThe rider's sex, M or FOptional — a heading containing the word "sex". Male/Female and M/F both import; blank means unknown, and any other value is a conflict unless the preview's Map unknown sex to Male option is ticked.

Any column whose heading matches nothing is ignored — a registration export's extra columns pass through untouched. If two columns match the same field, the first one wins. The app's own export always writes the canonical headers above, in that order.

Rows that are not riders

Trailing blank lines and footer rows (neither a first nor a last name) are skipped automatically — unless such a row still names a plate, team or type, in which case it is reported as a missing name rather than silently dropped.

Example

FIRSTNAME,LASTNAME,TYPE,TEAMNAME,NUMBER,NOTES
Luca,Ferrari,solo,,7,
Dev,Patel,team,Moss Ridge Riders,,shifts at the hour
Jo,Lindqvist,team,Moss Ridge Riders,,shifts at the hour
Casey,Muir,team,Moss Ridge Riders,,
Sam,Ellis,solo,,,

How plates are assigned

  • Blank numbers — rows with no NUMBER are given sequential free plates (skipping every plate already in use in the ride or named elsewhere in the file), in file order.
  • Rider-pooled rides — each row's NUMBER is that rider's own plate; a team is the riders sharing a TEAMNAME, and the team's entry adopts its lowest-numbered member's plate.
  • Team-relay rides — a team rides one plate, so all of that team's rows must carry the same NUMBER (or all be blank); solo rows carry their own plates.

Importing

The import preview reports how many riders, teams and conflicts the file contains and lists every problem row before anything is written — nothing changes until you confirm. Match-and-merge works by plate: an existing plate updates that entry in place (including a solo rider's name), a new plate is added. Re-importing freely reshapes teams while the ride is a draft; once a ride has started, only new plates and name fixes are accepted and anything structural is listed as a conflict.

Two options on the preview change how the file is read, and ticking either re-runs the preview in place. Map unknown sex to Male — tick it when a file's SEX cells are blank or use values the app doesn't recognise, but the riders are known to be male: every rider without a recognised M/F then imports as male. Left unticked, a blank SEX stays unknown and any unrecognised value is listed as a conflict. Convert teams of 1 to solo — tick it when a registration export writes one-rider "teams" that are really solo riders: each such group then imports as that rider's solo entry. Left unticked, a one-rider team is flagged as below the two-rider minimum — a warning while the ride is a draft, a blocking conflict once the ride has started. The conversion is draft-only: on a started ride the row stays a team and is reported as a conflict.

Conflict messages

  • Missing or malformed header — no column could be read as a first or last name.
  • Missing name — a row with no first or last name that still names a plate, team or type; or a team row with no team name.
  • Duplicate plate within the file — two rows claim the same plate.
  • Unknown entry type — a TYPE value that is neither solo nor team.
  • Team too small / too large — fewer than 2 riders, or more than the ride's max riders per team.
  • Structural change while running — e.g. solo → team on a ride that already started; new plates and name fixes only.
  • Team rows carry different plates — on a relay ride, a team's rows must name the same plate.

A finished-ride export adds four columns after the roster columns: laps, cards, best_hand and total_time.
