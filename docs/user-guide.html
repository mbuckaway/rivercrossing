1 · Getting started

RiverCrossing is a keyboard-first desktop app for Windows and macOS. The operator types a rider's plate number and presses Enter at each lap crossing; the app records the lap, deals a card from a seeded virtual shoe, and at the finish scores every entry's best 5-card poker hand.

About RiverCrossing

Version and credits live in Help ▸ About RiverCrossing. The version shown there comes from the installed package, so it always matches the build you are running.

Installing

  • Windows: run the installer and follow the prompts. Windows may show a SmartScreen "More info → Run anyway" step on the unsigned build — the guide documents that step so volunteers can get past it safely.
  • macOS: drag the app into Applications (or open the DMG and copy it), then launch. Gatekeeper may ask you to confirm opening an unsigned app once.

First launch & the ride library

The app opens on the timing console. File ▸ Ride Library lists every ride in the database — one database, every event. From the library you can open an existing ride, create a new one, duplicate one (copies setup + riders, no timing data), or delete one (you must type the ride's name to confirm, and a backup is written first). A running ride is never deletable.

Settings

File ▸ Settings (or the app menu on macOS) controls the operator-comfort layer:

  • Appearance — System (follow the OS), Light, or Dark. All three work on both platforms. On Windows a change applies at next launch; macOS applies it live.
  • Sound on crossing — three cues: a click when a crossing records, a two-tone alert when a short lap holds its card, and a buzz for an unknown plate or empty entry.
  • Hide times on the console — hides lap/total times mid-ride (it's-not-a-race mode). Times are still recorded underneath. The ride clock stays.
  • Text zoom — 90–150%, the same ladder as the View ▸ Zoom menu.
  • Back up now — writes a backup immediately.

The View menu mirrors Settings: Theme radios, Hide Times, and the Zoom radios. One setting, two places — they stay in sync.

Where your data lives

All rides live in one SQLite database (rides.db) in your user data folder. Every crossing commits as it happens (WAL journal), so a crash loses at most a keystroke. Backups are written on open and hourly while a ride runs, kept in a <db>.backups/ sibling folder, pruned to the newest 20.

2 · Setting up a ride

Create a ride from File ▸ New Ride…, or open an existing one from the ride library. Ride ▸ Ride Setup… reopens the setup window for the current ride while it is still a draft.

  • Name, date, venue, organizer, scorer, logo — the identity shown on the console and in published results. The logo file is embedded in exports.
  • Planned start & duration — the riding window; the console counts down the time to close.
  • Lap length & minimum lap time — a crossing faster than the minimum is flagged and its card held for review (a mistyped plate or a double entry usually explains it).
  • Entries — solo only, or solo + teams with a max riders-per-team (2–10, default 4).
  • Plate model — rider-pooled (default): every rider has their own plate and draws one card per lap, uncapped; the team's hand scores from the pooled cards. Team-relay: one plate per team, one rider on course at a time.
  • The shoe — decks (default 8) and jokers per deck (0, 2, or 4; default 2). All decks are shuffled together and dealt in order; the shoe reshuffles automatically if it empties.
  • Card cap — optional cap on cards per entry; laps still count past the cap.
  • Tie-break order — how identical best hands are resolved: ① most laps, ② shortest total time, ③ high-card draw at the venue. The order can be changed on the results screen before export.

Setup locks tighten once the ride starts: structural changes (entry mode, plate model, team size) are frozen, while name-only fixes stay possible in a running ride.

3 · Riders & entries

Riders ▸ Rider Editor manages the roster: plates, names, and teams.

  • Add a solo rider or a team; plates are unique across the ride, and a new entry's plate is prefilled with the next free number.
  • Delete is available while the ride is a draft; once an entry has recorded data, it is never removed — entries are marked DNF or their crossings voided instead (R-15).
  • Import / export CSV — bring a roster in from a file or write one out. The import preview lists every conflict before anything is written, so you can fix the file and re-import freely until the ride starts (see Appendix B).
  • Teams can be reshaped up to the start; on a pooled ride, moves stay possible while running and every move is audit-logged.

4 · Running the ride

The console is keyboard-first: the operator types a plate and presses Enter.

  • Start — press Start Ride. Missed the gun? Ride ▸ Set Start Time… back-dates the start and recomputes lap-1 times.
  • Record a crossing — type the plate, press Enter (or click Record). The crossing commits instantly, a card is dealt from the shoe, and the feed updates.
  • The sounds — a click on every recorded crossing, a two-tone alert when a short lap holds its card, and a buzz for an unknown plate or an empty entry. Toggle them in Settings.
  • Undo — Ctrl+Z (or the Undo button) removes the last crossing and returns its card.
  • Short-lap review — a lap under the minimum is flagged; its card is held until you confirm or void it in the review panel.
  • Relay teams — one rider per team is on course at a time; the crossing credits the team.
  • Hide times — Settings (or the View menu) can hide lap/total times mid-ride; times are still recorded underneath and the ride clock stays visible.

5 · Fixing mistakes

Every correction is a command with a reason, and every one is written to the audit log — nothing is ever deleted, only voided or edited (R-33).

  • Undo last crossing — the fastest fix for a mistyped plate.
  • Edit a crossing — change its time, or void it. Later lap times for the entry recompute automatically.
  • Add a crossing at time — a rider missed at the line; give the plate and the exact time.
  • Reassign a plate — move a crossing to the plate it belonged to; the card moves with it.
  • Deal / void a manual card — fix a mis-dealt card; a manual deal takes the next card from the shoe.
  • Mark DNF — an entry that did not finish keeps its laps and cards and is listed in the DNF block. Reversible.
  • Audit trail — Ride ▸ Audit Trail… shows every action (who, when, what, entry, reason), newest first, with plate search and action filters.

The Entry Detail window shows one entry's laps, cards, and current hand, with the correction buttons (edit crossing, deal/void card, move rider, mark DNF) on the same screen.

6 · Stopping, quitting & recovery

  • Stop — arm the checkbox beside Stop, then confirm. Stopping locks the entry field; the clock keeps running on wall time, so nothing is lost, and Start resumes whenever you are ready.
  • Quit with a ride running — the exit dialog offers Cancel, Finish ride first…, or Quit — keep ride running. Quitting keeps the ride live on the wall clock; the next launch asks you to continue it (the resume dialog says whether the last exit was a clean quit or a crash).
  • Crash recovery — every crossing commits as it happens, so a crash loses at most a keystroke. The clock is wall time, so elapsed time is never lost either.
  • Backups — written on open and hourly while a ride runs, kept in a <db>.backups/ folder (newest 20). File ▸ Back Up Database… or Settings ▸ Back up now writes one on demand.

7 · Finishing & standings

  • Finish ride — Ride ▸ Finish Ride… locks entry, runs the hand evaluator's self-test (a red self-test blocks finishing, R-44), and computes the final standings. The results window opens.
  • Pre-publish checks — held cards resolved, DNF entries included and marked, evaluator self-test passed.
  • Ties — identical best hands are resolved by the ride's tie-break order (most laps, then total time, then high-card draw). The order can be changed on the results screen before export and the standings re-rank instantly.
  • Reopen for corrections — Ride ▸ Reopen Ride reopens a finished ride for corrections: entry is locked, edits are highlighted in the feed, and Finish again re-locks and re-ranks. A published export is marked stale after corrections until you regenerate it.

The Results window shows the full field with place, plate, entry, laps, best-5 cards, and the hand name, plus the publish options (below).

8 · Publishing results

  • HTML export — one self-contained file you can post anywhere. Options: show lap & total times (off by default; with times off, no time data is embedded in the file at all), laps leaderboard, fastest-time leaderboard, full field, all cards drawn, and the organizer logo.
  • PDF report — the same sections as the HTML export, as a printable document.
  • Podium poster — a single celebratory page with the top three hands, for the prize table.
  • Standings CSV — place, plate, entry, laps, hand (and times when shown).
  • Preview in Browser — opens the last HTML export in your default browser.

9 · Poker, the run way

It is not a race — it is a poker run. Each completed lap deals one card; at the finish, every entry's best 5-card hand from all cards drawn is scored. Jokers are wild: a joker plays as any card you need.

Hand rankings, best to worst:

  1. Five of a kind (with jokers)
  2. Straight flush
  3. Four of a kind
  4. Full house
  5. Flush
  6. Straight (the wheel — A-2-3-4-5 — counts)
  7. Three of a kind
  8. Two pair
  9. One pair
  10. High card

Duplicates across entries are expected — the shoe is shuffled, not dealt from a single deck — and the shoe reshuffles automatically if it empties. Two entries with identical best hands are resolved by the ride's tie-break order, never guessed.

10 · Troubleshooting & FAQ

  • Missed the start — use Ride ▸ Set Start Time… to back-date it; lap-1 times recompute.
  • Typed the wrong plate — undo the crossing, or edit/reassign it and record a reason.
  • A rider crossed twice — void the extra crossing (its card voids with it).
  • The shoe ran out — it reshuffles automatically; deals continue.
  • Moving the database to another machine — copy rides.db (and its .backups folder if you want the history). The app opens it in place on the new machine.
  • Restoring a backup — replace rides.db with the backup file, then relaunch.
  • Theme change on Windows — a dark/light switch applies at the next launch; the status bar says so.

Appendix B — CSV reference

Roster imports and exports use one row per rider in a pooled ride, or per entry in a solo/relay ride. Import matches on plate; conflicts are listed before anything is written.

Solo-only rides

Columns: plate, name, notes (optional).

Mixed rides (solo + teams)

Columns: plate, entry_name, type (solo or teamN, where N is the rider count, up to the ride's max), then one rider_1 … rider_N column per seat.

Example (mixed)

plate,entry_name,type,rider_1,rider_2
7,Luca Ferrari,solo,Luca Ferrari
88,Moss Ridge Riders,team2,Dev Patel,Jo Lindqvist

Conflict messages

  • Duplicate plate within the file — two rows claim the same plate.
  • Missing name — a row with no name.
  • Structural change while running — e.g. solo → team on a ride that already started; name fixes only.

Nothing is written until you confirm the import, and re-importing freely reshapes teams before the start.
