1 · Getting started

RiverCrossing is a keyboard-first desktop app for Windows and macOS. The operator types a rider's plate number and presses Enter at each lap crossing; the app records the lap, deals a card from a seeded virtual shoe, and at the finish scores every entry's best 5-card poker hand.

About RiverCrossing

Version and credits live in Help ▸ About RiverCrossing. The version shown there comes from the installed package, so it always matches the build you are running.

Installing

  • Windows: run the installer and follow the prompts. Windows may show a SmartScreen "More info → Run anyway" step on the unsigned build — the guide documents that step so volunteers can get past it safely.
  • macOS: drag the app into Applications (or open the DMG and copy it), then launch. Gatekeeper may ask you to confirm opening an unsigned app once.

First launch & the ride library

The app opens on the timing console. File ▸ Ride Library lists every ride in the database — one database, every event. From the library you can open an existing ride, create a new one, duplicate one (copies setup + riders, no timing data), or delete one (you must type the ride's name to confirm, and a backup is written first). A running ride is never deletable.

Settings

File ▸ Settings (or the app menu on macOS) controls the operator-comfort layer:

  • Appearance — System (follow the OS), Light, or Dark. All three work on both platforms. On Windows a change applies at next launch; macOS applies it live.
  • Sound on crossing — three cues: a click when a crossing records, a two-tone alert when a short lap holds its card, and a buzz for an unknown plate or empty entry.
  • Hide times on the console — hides lap/total times mid-ride (it's-not-a-race mode). Times are still recorded underneath. The ride clock stays.
  • Text zoom — 90–150%, the same ladder as the View ▸ Zoom menu.
  • Back up now — writes a backup immediately.

The View menu mirrors Settings: Theme radios, Hide Times, and the Zoom radios. One setting, two places — they stay in sync.

Where your data lives

All rides live in one SQLite database (rides.db) in your user data folder. Every crossing commits as it happens (WAL journal), so a crash loses at most a keystroke. Backups are written on open and hourly while a ride runs, kept in a <db>.backups/ sibling folder, pruned to the newest 20.
