RiverCrossing — XRC window designs (implementation truth · retires the Industry hi-fi mockups)
Native wxWidgets controls only, sizer-based, Windows look shown (identical structure on macOS). Every interactive control carries its xrc_name annotation — these are the XRC name attributes, canonical and frozen; standard buttons use stock IDs (wxID_OK, wxID_CANCEL, wxID_CLOSE, wxID_DELETE, wxID_EXIT, wxID_ABOUT). Naming rules + window↔file map: Spec §15b.
Canvas caveats (HTML approximation): browser form controls stand in for wx natives; exact spacing/fonts come from sizers + system fonts, not these pixels; sizes below are minimums expressed in dialog units at build time. Global code-side items (not expressible in XRC): ① wxDataViewListCtrl columns + row data + per-row attributes (bold flagged rows, red suits) — appended in code; ② card imagelist population (53 card bitmaps @1x/2x); ③ wxInfoBar message text + Show/Hide calls; ④ splitter sash position restore from settings; ⑤ menu enable/disable per ride state (§15); ⑥ theme: 4.2.5 baseline = macOS follows OS / Windows light; wxApp.SetAppearance on the wx 3.3+ upgrade. Everything else drawn here is declared in XRC.
